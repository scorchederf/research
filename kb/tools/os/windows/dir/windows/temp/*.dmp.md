**fullpath**:C:\Windows\Temp\*.dmp

# description

Dump files (`.dmp`) are memory snapshots of a crashing process written by Windows Error Reporting (WER) or debugging tools. Microsoft Learn documents WER LocalDumps, whose default `DumpFolder` is `%LOCALAPPDATA%\CrashDumps`; service crashes are written to service-specific profile folders. Related tools: WinDbg, CDB, Task Manager live dumps.

## simple description

> ### 2026-11-21 Claude said
> This pattern matches memory dump files sitting in the system-wide Windows temp folder. They usually come from crashing services, installers or diagnostic tools running as SYSTEM. A dump contains a copy of the process memory at the time it was written, which can include secrets. They are normally safe to delete but are useful for troubleshooting crashes.
>
> **SOC NOTE**: Attackers dump LSASS memory (T1003.001, e.g. via `comsvcs.dll MiniDump`, procdump, Task Manager) and often drop the output in `C:\Windows\Temp` with names like `lsass.dmp` or innocuous names. Any large .dmp in this folder created by a non-WER process, or followed by archive/exfil activity, should be treated as possible credential theft. Check Sysmon Event 11 (FileCreate) and Defender alerts.
>

# purpose

Learn does not document `C:\Windows\Temp` as a dump location specifically. WER can be configured through `HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps` values `DumpFolder`, `DumpCount` (default 10), `DumpType` (0 custom, 1 mini, 2 full) and `CustomDumpFlags` to collect user-mode dumps after a crash; per-application subkeys override global settings.
